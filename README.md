# 故事接龙：灵矽语音 + 设备端 / 私有 MCP

## 异步故事链接续：电话验收版

依次说“我要玩游戏”“故事接龙”，选择“和我玩”或“和以前的小伙伴玩”，并可以指定故事主题。选择以前的小伙伴时，系统匹配该主题下一整条故事；没有已保存的故事时，听完固定背景接一句，录音异步归档后作为第一层。下次选择同一主题，先听背景和按顺序播放的已有原声，再接下一层；孩子接完后 AI 不继续编故事。明确要求“开始一个新的故事”时可另建一条，同一主题的故事不会混合。单人验收允许匹配自己的故事；不会把以前的录音描述为实时在线的人。此前的零散录音没有自动拼成故事链，需要先录制新的一层。

电话版需要本机启动 GamingPlatform（默认 `127.0.0.1:18789`）并使用 `start-private.ps1 -CallDemo` 启动私有 MCP。录音从灵矽通话记录异步归档，挂断后需要等待后台完成；故事链只有在录音准备好后才加入。多段原声会合成为一段并保留前导静音，再通过现有 `linx_play` 播放。平台没有提供可靠的播放完成回执，电话里是否听到、播放顺序是否正确仍需实际验收。当前设备身份使用单人测试身份，不能作为多设备身份验证结果。

本文后续旧版“以前伙伴按语境选一条录音”的描述保留作历史说明；启用 `STORY_CHAIN_DEMO=1` 时以上述故事链流程为准。

一个本地开发演示：浏览器模拟设备，Go 程序维护故事并执行 MCP，灵矽负责 ASR / LLM / TTS。支持设备端 MCP 与账号私有 MCP Proxy 两种模式，无需单独购买服务器。

模块图、各模块进度和验收计划见 [游戏大厅架构](ARCHITECTURE.md)。
固定电话验收话术见 [电话验收场景](PHONE-TESTS.md)。

当前为实验原型：电话测试已找到历史录音并发出播放请求，但验收者尚未听到原声；实体设备间的原声交付也尚未验收。浏览器演示不能代替电话或真机验收。

## 模拟灵矽多人闭环

不填密钥也能试大厅、声音传递和跨局复用：启动 `go run .`，打开 `http://127.0.0.1:8787/mock.html`，再在页面中打开伙伴 A、B、C。三个页面分别输入「我要玩游戏」和「我要玩故事接龙」，三人加入后 A 可以录一段声音，B、C 听完后轮流接话。房主结束整局后，其他伙伴重新加入相同语境，选择「找以前的伙伴」，可以听到其他人已保存的原声。

这里的伙伴是确定性模拟：输入文字代替灵矽的语音识别和意图判断，页面的麦克风录音、服务转发、原声保存和浏览器播放为真实实现。浏览器实际播放完毕才回报结果。此路径使用本地模拟协议，不能直接连接真实电话或小智设备，也不验证真实灵矽的 ASR、Buddy 或音频下行。

## 灵矽电话单人验收

本模式将专用智能体接入私有 MCP Proxy。用灵矽平台的通话入口，或用已经绑定该智能体的实体盒子，就能通过语音进入游戏大厅。启动时只为指定的故事接龙演示智能体打开「文本＋语音」聊天记录。使用私有试玩智能体，仅由本次验收者拨打。

电话工具为每次进入大厅分配独立的随机凭据，避免并发的单人故事相互覆盖。说要和在线玩家玩时，使用三分钟大厅匹配。当前多人 MCP 工具可查询局面和提交文字，还需要确认灵矽会话的原声交付及通知能力，真实语音以电话或盒子听到的内容验收。

~~~powershell
.\start-private.ps1 -CallDemo -AgentId <专用AgentID> -FFmpegPath <ffmpeg.exe绝对路径>
~~~

API Key 在本机隐藏输入。FFmpeg 已在 PATH 时可省略该参数。启动完成后，http://127.0.0.1:8788/api/status 可查看私有 MCP 是否在线、候选和筛选结果、原声准备阶段，以及原声播放请求数。窗口保持打开时，开发重载可以复用本次进程内的 Key。

1. 给专用智能体打电话，说「我要玩游戏」，再说「我要玩故事接龙」。默认主题是「森林冒险」，Buddy 开场。
2. 听完开场，接一句有辨识度、容易接入故事的对白，例如「小狐狸听见树洞里传来叮叮声」，接完说「不玩了」并挂断。
3. 第二次进入大厅时明确说想跟以前的伙伴原声玩，再进同主题。听完开场后，说一句与历史对白能衔接的上文，例如「小狐狸走进森林，停在一棵有树洞的树旁」。命中的历史原声作为队友回答，听完继续接下一句。没有合适片段时由 Buddy 接话。

每次有效发言按局保存故事标题、上句、回合标记和原样转写。选择历史伙伴时，大厅检索同标题、已归档且本局未用的录音，标题别名归入同一索引。关键词只用于候选排序，Buddy 结合最近故事、每段录音的原话和原来的上一句判断是否能自然接话。没有合适录音时，Buddy 接备用句。专用电话 Demo 的录音池按 Agent 隔离，允许同一个测试者不同局之间复用。当前版本每轮最多提供十二条候选，Buddy 用一次后续工具调用提交选中编号。

录音由灵矽在通话历史中异步写入。首次使用时，大厅按回合标记和相邻发言确认原声，转为 MP3 后存入私有对象存储。大厅确认临时地址可读后，向当前通话发出 `linx_play`。状态页的原声播放请求数表示动作已提交，电话或盒子里实际听到原声才算验收通过。

电话实测：平台先播报「为您播放队友接龙」，短原声可能被覆盖。诊断时给录音前添加 4 秒静音后，验收者听到了原声；这不能消除平台播报。默认不启用该临时方案；仅在需要复现诊断时，启动前设置进程环境变量 `STORY_CALL_PLAYBACK_DELAY_TEST=1`。历史原声会保留，另存一份带静音的私有播放副本。真正的自然接话仍需平台提供不播报提示的音频播放能力。

相关接口见 [灵矽聊天记录 API](https://linx.qiniu.com/docs/xrobot/api/chat-history) 和 [云端 MCP 播放动作](https://linx.qiniu.com/docs/xrobot/mcp/software-mcp)。

## 三盒游戏大厅 Demo

用三个浏览器标签页分别模拟盒子 A、B、C。大厅由同一个 Go 服务运行，按语境匹配，线上原声和历史原声使用同一套逐设备播放状态。这个入口启动后即可用麦克风录音和播放原声，无需灵矽 API Key。

~~~powershell
go run .
~~~

打开 [本地大厅](http://127.0.0.1:8787/lobby.html)，在页面上依次打开 A、B、C。浏览器支持时，可以点「语音唤醒」后说「玩故事接龙」。也可以直接点「加入故事接龙」。录音用「开始说话」「说完了」，请允许麦克风权限。

1. **三分钟匹配和中途加入。** 三台盒子选择同一语境。三台到齐立即开局，三分钟到时已有两台也会开局。只剩一台时继续等待，或点击「和历史伙伴玩」。两人局开局后，C 可加入并从下一句开始参与。
2. **三盒轮流。** A 点「开始说话」，B 可以在 A 说完前听见。A 说完后，B 的播放器实际结束才交棒。B 发言时，A 和 C 各有一次独立播放。C 可试「本机停播」，A 继续听。三台盒子都可以在轮到自己时接一句。
3. **保存和跨局复用。** A 说一句能独立开头的话，页面上「把这句原声留给以后的伙伴」默认选中，点「说完了」。等页面确认已入池，让 A 点「结束整局」并关闭 A。B 选回同一语境加入，选择「和历史伙伴玩」。B 会先听到 A 留下的原声，听完接一句，历史席位再从池里取另一条没听过的原声接回来，如此逐棒交替。
4. **九棒收尾。** 故事接满 9 句后不再交棒，等最后一段播完，页面显示完整故事供回顾。

匹配最多等三分钟，三人到齐时提前开始。等待期结束时有至少两人就开始，只有一人可继续等、主动选历史伙伴，或在加入时勾选匹配失败后使用历史原声。故事原声保存在故事接龙服务的池里，供同游戏跨局使用。房间运行在内存中，原声可跨服务重启使用。首版按语境筛选并随机选原声，同一局不重复取同一条，也不会把自己以前的声音当成历史伙伴；池里这个语境没有别人的原声时，由真人继续接，不降级使用自己的录音。留存默认开启，取消勾选则该句只在本局使用。完整 PCM 写盘在系统用户缓存下的 `story-relay-mcp/clips`。Demo 每句录音上限 30 秒。

### 真机接入和 Issue #15

已有私有 MCP Proxy 会同时发布 `self.lobby.join`、`self.lobby.status`、`self.lobby.speak`、`self.lobby.leave`。使用已绑定的专用 Demo Agent 时，可以语音进大厅、匹配、查当前局和提交文字回合。每个盒子保留自己取得的随机 `ticket`，它是本 Demo 的座位凭据。正式接入应绑定灵矽提供的可信设备或玩家身份。当前这条 MCP 链路的媒体状态会明确返回 `transcript_only`。

浏览器版本实现的是本地媒体适配。真机需要通过灵矽的 App 边界取得获授权的 A 原声，再由游戏为 B 和 C 分别创建播放。Issue #15 中待新增的能力是 **App 提交的原声下行到指定设备**。接口验收包括：

| 能力 | 游戏侧需要什么 |
| --- | --- |
| 建立播放 | 提供目标实例和该设备支持的音频格式，收到绑定目标连接的播放编号。 |
| 写入原声 | 按播放编号写入原声音频帧，同一路输入可由游戏分别发给多个目标。 |
| 正常结束和定向停播 | 正常结束保留尾音。停止指定播放时，清掉该设备的未播缓冲。 |
| 逐设备播放终态 | 回报实际播完、停播或失败。服务端发送完成可单独记录，下一棒等待自己的播放结果。 |

原声上行订阅是 App 接入的联调前提。现有 MCP Proxy 的文字工具可单独验证大厅业务。这次本地验证通过浏览器麦克风、WebSocket 和播放器，真机还需要受信 App 连接、原声上行和上述下行能力。[灵矽接入需求 Issue #15](https://github.com/qbox/linx-box/issues/15)

## 私有 MCP Proxy 模式

启动后会将故事工具注册到你自己的灵矽账号，设备端不再上报同名工具：

```text
浏览器 / 硬件 ↔ 灵矽智能体 → 账号内私有 MCP → 灵矽 MCP Proxy ↔ 本机故事工具
```

浏览器演示的音频仍由本地网关桥接；支持灵矽的硬件理论上可以连接绑定了私有 MCP 的智能体，具体需根据硬件完成接入并实测。代码和游戏状态在本机执行，私有 MCP 的服务记录、开通实例及智能体绑定存在灵矽账号中。关闭电脑或程序后工具会离线。

在本目录启动：

```powershell
.\start-private.ps1
```

脚本会询问专用 Agent ID 与 API Key，Key 隐藏输入，只传入当前进程环境，不保存文件或修改用户永久环境变量。关闭窗口或 Ctrl+C 停止。启动前先关闭已运行的本地程序，避免同账号同时运行多个 MCP Proxy 实例。

先在灵矽控制台创建名为“故事接龙·私有演示”的专用智能体，并复制其 Agent ID；启动流程会同步该专用角色的提示词，避免覆盖其他智能体。

等价环境配置为 `LINX_API_KEY`、`LINX_AGENT_ID`、`STORY_MCP_MODE=proxy` 后执行 `go run .`。程序会：

1. 查询 Key 对应的内部账号用户名。七牛 SSO 账号的内部用户名可能是数字 UID，不能当作登录手机号；页面明确标注为“平台账号标识”。
2. 获取当前账号的 MCP Proxy 凭据，主动建立 WSS 长连接；仅在 HTTPS 管理接口返回同源 WS 地址时升级为 WSS，始终使用 TLS。
3. 发布单人故事工具与多人大厅工具，创建或复用“故事接龙·私有MCP”，明确设置 `is_private=true`。其发布状态表示私有记录可开通，不表示公开到公共市场。
4. 创建或更新自己的开通实例，把代理凭据配置到 `X-MCP-Token` Header；凭据不出现在本地状态接口、页面或日志。
5. 保留目标智能体已有的 MCP 绑定，追加本服务，同步专用故事提示词。

控制台对应入口：“自定义 MCP”查看服务定义；“我的 MCP”查看开通实例；“我的智能体”进入专用角色查看绑定。MCP Proxy 凭据通常30天有效，页面显示实际到期时间；到期后用 Key 重启程序，自动获取新凭据并更新现有实例，不重复创建服务。

Proxy 当前不转发设备/会话身份，因此工具在 start 返回随机 `story_id`，continue/end 必须携带它。浏览器另通过提示词替换传入随机 `session_key`，仅用于将该连接的工具执行结果推回页面；没有此字段的硬件调用仍可依赖返回的 story_id 独立游戏，不使用账号级共享故事。

浏览器断连会清理其故事；其他故事在下次工具调用时清理30分钟未活动的记录，进程重启不恢复。浏览器的沉默结束继续由其播放完成事件计时；硬件直接连接灵矽时，工具本身无法感知最后一帧的播放时间，完全相同的沉默策略还需硬件事件或平台空闲策略配合，当前未把硬件链路当作已验收。

## 运行

需要 Go 1.26.1 或更高版本、Chrome / Edge、灵矽 API Key。首次连接时会在你的灵矽账号创建专用的“故事接龙·本地演示”智能体，并为浏览器生成的虚拟 MAC 预注册、激活。只用于本演示，不填写已有硬件的 MAC。

```powershell
cd story-relay-mcp
go run .
```

打开 http://127.0.0.1:8787，在密码框填写完整 API Key，选择“新建专用故事智能体”，点击“连接并开始”。页面拿到新 Agent ID 后会记住非敏感的 Agent ID 与虚拟 MAC，之后复用。API Key 不写文件、不记日志、不存 localStorage，断连后重新填写；可改用 `LINX_API_KEY` 环境变量。

API ID 是密钥记录的标识，不是 Agent ID，本演示不需要它。首次创建也不要求已有 Agent ID。使用现有智能体时，取消新建选项，填写 Agent ID，并先在控制台把本目录 `prompt.txt` 配置为系统提示词，意图设为 `Intent_function_call`；程序不会修改已有智能体提示词。

连接成功后点击“开启麦克风”，允许浏览器使用麦克风。也可以用文字输入验证相同的灵矽 → MCP → 游戏状态链路。

## 玩一轮

1. 选“小星先开头”并连接：AI 调用 `self.story.start`，页面出现第一句，并播放语音。
2. 开启麦克风，说“它在门后发现了一只戴帽子的兔子”：AI 调用 `self.story.continue`，记录孩子与 AI 各一句。
3. 说“换个故事”或点击按钮：AI 再次调用 start，新故事替换当前故事。
4. 说“结束故事”或让情节自然收尾：AI 调用 `self.story.end`。
5. AI 的音频实际播放完毕后开始等待，默认 60 秒没有孩子继续发言就结束。不催促孩子。调试可选择 15 秒。

选“我先开头”时，欢迎语后等待孩子第一句，再通过 start 保存孩子开头与 AI 接句。右侧显示真实的 `initialize`、`tools/list`、`tools/call`；点击按钮或打字也交给灵矽决定工具调用，不在页面伪造 MCP 成功。

## 原单人故事屋的边界与配置

- 游戏状态仅存在当前本地会话内存，断连不恢复；页面会保留已显示的故事供查看。没有音频文件保存或数据库。语音会发送到灵矽，平台侧记录策略需在灵矽控制台配置。
- 沉默结束是本地计时逻辑，通过 `listen.detect.text_response` 播放结束语，不伪装成 AI 发起的 MCP 调用。
- 音频使用 16kHz、单声道 PCM16，20ms 一帧；遵循服务端 hello 的下行音频参数。服务端需支持 PCM，避免本地安装 Opus/CGO。
- 当前只监听回环地址，面向开发验证。公网部署需要增加应用认证、会话持久化和 HTTPS；硬件接入需要实现相同的浏览器到本地网关消息协议，或另做硬件协议适配。
- 关闭程序不会删除灵矽账号下已创建的智能体或设备，可以在灵矽控制台管理。

| 环境变量 | 默认值 / 作用 |
| --- | --- |
| `STORY_ADDR` | `127.0.0.1:8787`，仅支持回环地址 |
| `LINX_API_KEY` | 无默认值；API 认证，只在服务端内存使用 |
| `LINX_AGENT_ID` | 可选，使用已配置好的智能体 |
| `LINX_API_BASE` | `https://xrobo.qiniu.com` |
| `LINX_OTA_URL` | API base + `/xiaozhi/ota/` |
| `LINX_WS_URL` | `wss://xrobo-io.qiniuapi.com/v1/ws/`；OTA 返回地址时优先使用 |
| `STORY_MCP_MODE` | 默认 `device`，设为 `proxy` 启动账号私有 MCP |

本地 HTTP API 仅 `GET /api/status`，响应为 `{code,msg,reqid,data}`，不包含密钥。Proxy 模式额外返回账号内部用户名、Agent / MCP 标识、代理在线状态、到期时间与调用计数。`/ws` 是浏览器网关，不是公网 HTTP MCP 端点；设备端模式通过语音连接提供工具，Proxy 模式通过独立 WSS 连接向平台的 `/v1/mcpproxy/mcp` 端点提供工具。

故障定位：API 401 检查 Key；未绑定提示检查设备激活；MCP 没有列出检查意图模式；只有文字没有声音检查浏览器音频权限；有 AI 回答但没有工具调用检查模型的工具能力及系统提示词。语音尚未连接时不会用假故事替代真实调用。

## 浏览器网关协议

浏览器连接本地 `/ws`，Origin 必须与页面一致。第一条文本消息为 `{"type":"connect","options":{...}}`。`options` 包含 `api_key`（可用服务端环境变量替代）、`agent_id`、`device_id`（MAC）、`create_agent`（bool）、`first_speaker`（`ai` / `child`）、`silence_seconds`（15–300，默认60），可选 `opening` 为孩子的首句。新建模式忽略已有 Agent ID，不修改其他智能体。

后续文本消息格式为 `{type,text?}`：

| type | 含义 |
| --- | --- |
| `text` | `text` 是用户输入的一句，最多400字，通过灵矽触发工具 |
| `replace` | 请求 AI 新开一个故事 |
| `end` | 请求 AI 调用结束工具 |
| `interrupt` | 中止当前 AI 播放 |
| `voice.activity` | 麦克风检测到声音，延后等待计时 |
| `playback.done` | 下行音频真正播放完毕，开始等待孩子 |

上行二进制帧为16kHz、单声道、little-endian PCM16，每帧320采样（20ms）。下行二进制遵循 `platform.data.audio_params`。同一连接的文本与二进制按发送顺序处理。

服务端文本格式为 `{type,text?,data?}`：`phase` 是连接阶段及非敏感设备身份；`ready` 表示工具列表已回复灵矽；`error` 是可展示的错误提示；`platform` 是脱敏后的 hello / STT / TTS；`trace` 记录请求方法、工具名、请求ID与成功状态；`story` 是 `{id,title,status,reason?,lines:[{role,text}]}`。`status` 为 `ready` / `playing` / `ended`，结束原因是 `child_stop` / `ai_finish` / `silence`。断连后不重放或恢复旧状态。

灵矽侧复用官方 WebSocket 的 `hello` / `listen` / `mcp` 格式，MCP 通过 `payload` 承载 JSON-RPC 2.0。`initialize` 返回版本 `2024-11-05`，`tools/list` 一次返回三个工具，无后续分页。`tools/call` 结果为 `content:[{type:"text",text:...}]` 和 `isError`；业务校验失败不更新故事，未知 RPC 方法返回 `-32601`，错误参数返回 `-32602`。

灵矽管理接口的设备预注册响应是 `{success_count,failed}` 裸对象，与其他管理接口的 `{code,msg,data}` 不同，在接入边界明确处理。
