# 灵矽语音游戏大厅架构简图

## 设计重点

- **产品形态。** 孩子带着自己的 Buddy，通过无屏幕盒子进大厅。可以和 Buddy 玩、约在线好友同局，也可以接着好友之前留下的原声玩。
- **楼与房间。** 一楼提供选房、好友邀约、场次和语音复用。二楼的房间定义玩法、回合、判定和素材适用条件。首个房间用故事接龙验证整栋楼。
- **声音怎么走。** 首版用半双工短回合。轮到谁就收谁的一句，区分游戏动作与私人控制后，再把有效原声播给指定盒子。孩子可以在本机停播、退出或换游戏。播完再开麦需要真机验证。
- **声音怎么留。** 在线回合使用短时缓冲。获准复用的原声存入私有对象存储，语音池保存索引、适用条件和权限。原局结束后，新局仍可按条件取用，播放前复核授权。
- **两个仓库。** xrobotd 负责可信语音会话、原声采播和本机控制。GamingPlatform 独立承载大厅和玩法，MCP 用于开局、提交动作和查询局面，宿主适配负责对端播报。

## 模块树

~~~text
灵矽语音游戏大厅
├─ 仓库一 · xrobotd
│  ├─ 设备会话与私人 Buddy
│  ├─ 原声采集、定向播放、播完交棒
│  └─ 本机私人控制 · 停播、退出、换游戏
└─ 仓库二 · GamingPlatform
   ├─ 接入 · MCP 工具与宿主适配接口
   ├─ 一楼 · 公共平台
   │  ├─ 大厅 · 房型目录、选房、找回待续场次
   │  ├─ 好友邀约 · 邀请、接受、入座
   │  ├─ 场次 · 成员、发言权、回合交付、恢复
   │  └─ 语音复用池【优先】
   │     ├─ 音频对象 · 私有存储
   │     ├─ 复用条目 · 来源、适用条件、可见范围
   │     └─ 发布、检索、授权取用、撤回
   └─ 二楼 · 游戏房间
      └─ 故事接龙 · 规则、故事进度、素材条件
~~~

**首轮验收**　A 留原声后结束原局并离线。B 从另一台盒子开新局，听到这段原声并接一句。再验证两台盒子实时同局时，能否顺利交棒，以及孩子能否在播放中退出。
