# 语音游戏大厅 v0.2 架构评审补充

v0.2 的独立大厅、宿主适配和玩法分层可以作为共同底座。建议把跨局原声复用、半双工回合和孩子的私人控制写进首轮设计，确保两台盒子的 Demo 能同时验证产品体验和架构边界。

## 建议补进评审稿的设计

### 1. 把跨局原声复用列为一楼的公共能力

同局留言和跨局复用各有一个闭环。**同局留言**让 A 留一句，B 有空时回到原来那局继续。**跨局复用**让原局已经结束、A 已经离线时，B 仍能开一局新游戏，由大厅按房间给出的条件找到 A 留下的原声，再把它用进当前局。这条链路决定语音池能否持续积累可玩的内容。

| 对象 | 责任 |
| --- | --- |
| 音频对象 | 记录原声的私有存储引用、格式和时长。 |
| 复用条目 | 记录贡献者、来源场次和动作、素材类型与版本、适用条件、可见范围、有效期和撤回状态。 |
| 二楼房间 | 决定哪些动作可以发布、当前局需要哪种素材，以及这个素材怎样推进规则。 |
| 一楼语音池 | 提供发布、查找、授权取用和撤回。文件可读且获准分享后才进入索引，播放前按当前场次和接收者复核权限。 |

在线回合用短时缓冲完成交付。获准分享的原声独立入库，复用条目关联该文件。留存失败时，已确认的游戏回合仍能继续。MCP 的开局、提交和查询接口可以复用这套公共能力。

### 2. 首版通信采用半双工短回合

场次先授予发言权。语音侧收完一句，区分私人控制和游戏动作。游戏动作由房间接收后，再把原声播到指定盒子。在线同局与历史原声共用播放、取消和交棒。历史录音播放前，由 Buddy 简短说明它是好友之前留下的。

MCP 负责选房、提交动作和查询局面。好友无需先开口的定向播放，由宿主适配交付。**当前调用方能回放、对端能收到事件、对端扬声器实际播完**分别验收。交棒依赖下一位玩家的播放结果或超时处理。发言、播放指令和回执带场次及回合标识，重试去重，换房后旧指令失效。

设备侧优先沿用灵矽现有 WebSocket。跨仓控制请求与事件下发可先评估内部 HTTPS 加 SSE，音频走独立媒体路径。这个选择等两台实体盒子的播放、打断和恢复验证后冻结。

### 3. 把游戏动作与私人控制分开

| 孩子的行为 | 建议行为 |
| --- | --- |
| 别人正在说时插话或抢答 | 只有房间明确开了相应窗口，才接收为游戏动作。普通插话留在当前盒子。 |
| 说「停一下」 | 优先停止本机播放，保留场次，由 Buddy 确认后续选择。 |
| 明确说「不玩了」或「换游戏」 | 停止本机游戏采播并交还 Buddy。场次释放席位和发言权，房间决定这局如何继续。 |

孩子和私人 Buddy 是进大厅的玩家单位。Buddy 取得当前孩子可见的局面和可用动作，负责解释规则、提醒和表达选择。场次负责发言权，房间负责判定和推进。

### 4. 用一楼的接口验收新增房间

一楼维护房型目录、好友邀约、场次和席位、动作与结果交付、语音复用池。二楼房型提供规则、内容、玩家可见局面和素材条件。先把房型和场次设计为独立对象，玩法服务是否独立部署可随开发阶段决定。首轮用第二个简单规则模块走一遍同样的进房、提交、取用原声和退出接口，检查新增玩法的改动是否集中在房间。

## 建议的首轮验证顺序

1. **先验证复用池。** 用故事接龙跑通 A 录一句并确认分享，结束原局并离线。B 从另一台盒子开新局，听到 A 的原声并接一句。再验证素材撤回后，尚未播放的场次取不到它。
2. **再验证好友实时同局。** 两台 xAtom 接受邀请并入座，独立验证对端无需先开口即可听到、播放完成后可以接话，以及抢答、退出和重连时场次仍然一致。记录说完到对端首声、对端播完到开麦的 P50 和 P95。
3. **验证房型扩展和宿主适配。** 用另一间房复用同一套接口。保留 v0.2 的可信身份绑定和宿主能力声明，小智按独立的录音、原声播放和定向交付验证结果开放相应模式。

## 评审需要回答的问题

| 优先级 | 问题 |
| --- | --- |
| P0 | **xAtom 的原声链路在哪里接。** 已有 MCP 能跑哪些动作？采集经确认的原声、送到另一台盒子、取消在播音频各要用哪条接口？哪些能力需要灵矽侧补接入？ |
| P0 | **能不能确认盒子实际播完。** 有扬声器播放完成信号，还是只能从发送完成和设备缓冲推算？弱网下怎么交棒，避免抢开麦、截字或让一台慢设备卡住整局？ |
| P0 | **怎么随时退出。** 盒子在播放时，孩子可以通过唤醒词、实体键或哪种设备事件触发私人控制？如何区分故事里说的「不玩了」和孩子确实要离开？ |
| P0 | **谁能匹配和听到原声。** 首轮好友关系与可信玩家身份从哪里取？原声可以播给指定好友、同一组好友，还是更大的范围？ |
| P0 | **哪些声音进入池子。** 孩子何时确认分享、默认保存多久？撤回后已经签发的授权、等待播放的指令和缓存怎样失效？ |
| P1 | **场次怎样开多局和恢复。** 同一房型是否同时开放多局？同一个孩子能挂起几局？好友上线、重连或换房时，待续入口和发言权怎样处理？ |
| P1 | **交付和部署边界何时冻结。** 首版是否沿用同一语音节点验证媒体链路？玩法逻辑是否先与大厅同进程部署？跨节点及小智适配需要补哪些能力测试？ |
